# BV1NG9xBUEju B站 AI 字幕机制研究

日期：2026-10-20

## 已验证事实

同一登录态、同一 Python 客户端对三个视频执行了相同的字幕路径：

| 视频 | `/x/player/wbi/v2` | `/x/v2/subtitle/web/view` | 结果 |
|---|---:|---:|---|
| `BV16hZFB5ERM` | 1 条，但旧轨归属错误 | 1 条 `ai-zh`，归属正确 | 成功 |
| `BV11gYd6UEPv` | 1 条，但旧轨归属错误 | 4 条，中文轨归属正确 | 成功 |
| `BV1NG9xBUEju` | 0 条（部分请求会返回异视频轨） | 0 条，响应为 2 字节空 Protobuf `0a00` | 失败 |

目标视频元数据为 `aid=116488438549326`、`cid=37950522219`。失败视频的现代接口空响应在以下参数变化下保持不变：当前参数、完全采用参考实现的参数（去掉 `arc_video_language` 与 `web_location`）、去掉语言偏好、去掉 `web_location`、切换 `playlist_switch`、中文语言偏好、平台/locale 参数和不同 `context_ext`。这排除了常见 query 参数缺失导致的空列表。

公开参考项目 `ccBilly-aipm/bilibili-ai-subtitle` 的源码采用同一条链路：先 `/x/player/wbi/v2`，再 `/x/v2/subtitle/web/view`，并使用 Protobuf 字段 1/3/5 解析。用同一登录态运行其提取器：`BV16hZFB5ERM` 返回 1 条 `ai-zh`，`BV1NG9xBUEju` 返回 0 条。它没有发现本项目遗漏的替代接口。

旧接口在目标视频上会出现两类结果：带其他 `aid/cid` 前缀的 `/bfs/ai_subtitle/prod/...` 资源，以及 `/bfs/subtitle/<opaque-id>` 资源。后者可以返回 HTTP 200，但一次探测只得到 1 条、约 27 秒范围的正文，URL 没有可验证的目标归属字段。它不能证明是目标视频完整字幕，不能直接缓存或导出。

## 失败链路

1. 视频身份解析成功。
2. 现代字幕元数据接口返回空轨道。
3. 旧接口返回的轨道无法通过 `aid+cid` 归属校验，或只提供不可验证的不透明资源。
4. BiliScribe 按设计拒绝缓存、下载和导出，正文下载函数不会执行，因此结果为 0 条字幕、0 个文件。

## 可能的解决方案

### 可安全实施

- 让浏览器播放器做一次真实请求并记录脱敏元数据：请求路径、查询参数名、响应轨道语言、`subtitle_url` 主机/路径结构和响应长度。重点确认播放器是否使用不同于 `/x/v2/subtitle/web/view` 的接口，或是否在 `SESSDATA` 之外依赖特定设备/会话 Cookie。
- 在本地客户端增加“浏览器请求诊断”模式，只记录上述脱敏字段，不记录 Cookie、签名参数或正文。拿到真实轨道后再补一个 mock 回归测试。
- 对 `/bfs/subtitle/<opaque-id>` 只做临时探测，不纳入自动导出；只有 B 站响应中有明确 `aid/cid` 或可验证的绑定字段时才允许缓存。
- 对现代接口返回空列表和旧接口串轨继续显示当前明确错误，避免把异视频字幕当成成功。

### 不应实施

- 取消中文轨道的 `aid/cid` 校验。
- 看到 HTTP 200 或正文非空就认为字幕属于当前视频。
- 把不透明 `/bfs/subtitle/` 资源永久缓存或直接导出。
- 用 ASR 代替已有 CC/AI 字幕；这会改变 BiliScribe 的产品边界。

## 当前结论

现有证据支持“B站为该视频返回的字幕元数据与其他视频不同/不完整”，不支持“BiliScribe 的 Protobuf 解码或 URL 下载实现有一个已定位的通用 bug”。在获得播放器真实请求前，最小且安全的修复是保持严格拒绝并改善诊断；真正恢复提取需要确认播放器使用的额外上下文或替代接口。

- `/x/v2/subtitle/web/view` 在完整参数、精简参数、附加播放器设备/语言头、WBI 签名等组合下都返回 `HTTP 200`、2 字节 `0a00`，解析为 0 条轨道。
- `/x/player/wbi/v2` 使用当前导航得到的 WBI 签名和浏览器常见设备头仍返回 0 条轨道；未签名旧接口则会偶发返回一条 `ai-zh`，但资源 ID 不含目标 `aid+cid` 前缀。
- 对旧接口偶发资源做了正文探测：不同轮次得到的正文条数和末尾时间轴明显不稳定（例如约 7/15 秒、20/33 秒、120/196 秒、675/1337 秒），不能证明是目标视频的完整字幕。服务因此保持拒绝导出。

## 2026-10-20 原因复核

使用当前本地登录态再次对目标视频和接口响应进行脱敏探测：

- `/x/player/v2` 在普通请求时返回 0 条；带不同缓存破坏参数的请求也会在 0 条和 1 条 `ai-zh` 之间变化。因此“旧接口永远没有返回字幕”不准确。
- 对一次带缓存破坏参数返回的旧轨，仅在内存中下载正文：HTTP 200，869 个字幕段，最大结束时间约 1660.28 秒。目标视频时长约 1225 秒；资源 ID 不含目标 `aid=116488438549326` 和 `cid=37950522219`，本项目归属校验拒绝该轨。未保存正文或签名 URL。
- 同轮 `/x/player/wbi/v2` 返回 0 条；`/x/v2/subtitle/web/view` 返回 2 字节空 Protobuf `0a00`，解析为 0 条轨道。
- 成功对照视频 `BV16hZFB5ERM` 使用相同本地登录态和 BiliScribe 路径，仍成功获取目标归属轨并生成文件。

### 原因判断

**已验证：**本次能观察到的差异发生在 B 站字幕列表响应上。新接口没有给出目标轨；旧接口偶发给出一个可下载但归属标识不符、时间轴也超过目标时长的 `ai-zh` 资源。正文下载机制本身能处理此类 JSON 响应，但该资源不能安全地视为目标视频字幕。成功对照排除了本项目 Protobuf 解析和下载逻辑普遍失效。

**最可能解释：**旧 `/x/player/v2` 在此视频上出现服务端/缓存层的轨道串配或陈旧数据。随机缓存参数仍能偶发得到该轨，说明不能简单归因于本地 24 小时缓存；但它不能排除 B 站边缘缓存、内部数据映射问题或请求上下文差异。

**仍未证实：**用户随后确认播放器字幕菜单中没有“中文 AI”。因此目前没有播放器可选目标轨的证据。内置浏览器标签的 Network 记录未能读取，无法确认页面加载/菜单操作时是否调用了其他字幕元数据接口，也无法区分 B 站服务端串轨、隐藏的播放器上下文差异或资源 ID 格式变化。不能仅凭 HTTP 200、`ai-zh` 标签或非空正文来断定归属。

### 解决路径

目前可安全落实的是拒绝不匹配轨道并给出明确错误；放宽归属规则会重新导出已出现的错误内容。用户已确认播放器没有可启用的“中文 AI”轨。若以后 B 站为该视频提供字幕轨，再通过播放器实际请求确认资源归属并做 mock 回归测试；在此之前没有依据增加字幕接口适配。ASR 不属于本产品的解决路径。

这次探测排除了“仅缺少 WBI 签名、`preferred_language`、`web_location` 或常见设备头”这类客户端参数遗漏。用户确认菜单没有“中文 AI”；内置浏览器标签绑定和 Network 读取多次超时，所以我无法独立检查该页面打开字幕菜单时的请求。已有请求快照未包含目标视频的字幕元数据请求。由于播放器无目标轨可启用，当前没有可供适配的播放器字幕响应。
