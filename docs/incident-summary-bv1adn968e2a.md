# BV1aDn968E2A 字幕提取故障总结

日期：2026-10-28（Asia/Shanghai）  
问题视频：[美国人讨厌AI吗？- 回答观众提问](https://www.bilibili.com/video/BV1aDn968E2A/)  
状态：已修复并完成本地验证；尚未部署云端版本。

## 现象

B站页面存在 AI 中文字幕，但 BiliScribe 提示没有字幕或字幕归属校验失败，没有生成用户选择的字幕文件。修复前的完整本地提取记录为 `no_subtitle`、0 条轨道、0 个文件。问题不是视频没有字幕，也不是本次提取需要 ASR。

## 原因

BiliScribe 已从 B 站现代字幕接口取得 `ai-zh` 轨道，但其资源 ID 是不透明的 32 位十六进制字符串 `e8edb3c0dc6f558b5b433ba24ec806be`，没有包含本视频 aid/cid 的可识别前缀。旧有归属规则在中文字幕路径上要求资源 ID 必须带目标视频的 aid+cid 前缀，于是把“无法从资源 ID 单独还原视频身份”错误地当成“已确认属于其他视频”。

现代轨道因此被过滤，客户端转而请求旧字幕接口；旧接口的候选又无法通过旧有归属检查，最终上层把失败表现成无字幕/归属错误。这样既丢失了可用的现代 AI 字幕，也混淆了“没有字幕”“无法验证”和“确认归属冲突”三种不同状态。本地 Python 客户端和云端 Worker 都有过度依赖资源 ID 前缀的逻辑。

诊断得到的现代轨道包含 252 段，最后一段结束于 822.77 秒；这些内容和时长可供人工核对，但本身不能作为归属证明。在线复现覆盖了本地客户端；云端相同假设是通过代码检查确认的，没有据此声称当时做过云端真实提取。

## 修复

- 对现代接口直接返回的受支持不透明资源，使用请求时由客户端建立的来源绑定：规范视频身份、目标分 P、具体轨道字段和校验策略版本相互绑定。只有地址通过安全校验、协议解析成功、绑定完整且没有明确冲突时，才按现代请求来源接收。
- 保留可识别资源身份的 aid/cid 校验；资源字段或可靠身份信息明确冲突时仍拒绝。旧接口、不明来源缓存或调用方自行构造的轨道不会因为资源 ID 不透明、作者相同、正文非空或时长相近而获得授权。
- 归属验证贯穿轨道发现、列表缓存读取、正文缓存与刷新、正文下载和最终导出。缓存按视频、分 P、稳定资源身份及来源/策略版本隔离；无足够来源证据的旧记录重新查询，不能直接用于导出。
- 现代有效轨道逐条保留，不因无关的无效轨道或旧接口结果丢弃。错误结果区分明确归属冲突、无法验证、列表为空、所选语言不可用、正文为空、登录/限流、网络和解析错误；字幕发现或正文错误不会被伪装成“无字幕”来触发 ASR。
- 对本地 Python/httpx 与 Worker 的失败分类、有限回退、语言选择、时间戳、文件名和五种导出格式做一致性回归。

这项来源绑定是有限的信任策略：它依赖 B 站现代接口按当前 pid/oid 返回对应视频的轨道。若服务端将其他视频的无冲突不透明资源错误放进合法响应，当前客户端未必能识别；因此不把来源绑定描述为资源 ID 自身的密码学归属证明。

## 验收结果

- 自动化回归只 mock 外部 B 站 HTTP/fetch；字幕列表发现、Protobuf 解析、地址解码、归属判定、缓存流程和导出继续运行真实代码。主要验收从公开提取入口走到实际导出或用户可见错误，并包含失败到通过的回归证据。
- 集成版本 Python 测试 94 项通过、离线维护测试 5 项通过、字幕保护脚本通过；Worker 构建后 39 项通过。Standards 与 Spec 双轴独立复审均无未解决项。
- 对目标视频进行两次真实本地 HTTP 提取，中文选择且 ASR 关闭；每次均得到 1 条 `ai-zh` 轨道及 SRT、VTT、TXT、JSON、Markdown 五种文件。252 段字幕结束于 822.77 秒；10 次 HTTP 下载内容均与实际生成文件逐字节一致。
- 修复前后摘要、格式校验值和验收边界见[最终验证记录](verification-subtitle-ownership.md)；审查过程与复审结论见[双轴审查记录](review-subtitle-ownership.md)。完整行为规范见[无前缀 AI 字幕兼容与归属验证规范](spec-subtitle-ownership.md)。
