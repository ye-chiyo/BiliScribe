# 无归属前缀 AI 字幕兼容与归属验证规范

日期：2026-10-27（Asia/Shanghai）  
状态：待实现；本文件定义目标行为，不代表修复已经上线。  
追踪：[本地 issue](../.scratch/subtitle-opaque-id-bv1adn968e2a/README.md)  
目标案例：[美国人讨厌AI吗？ - 回答观众提问](https://www.bilibili.com/video/BV1aDn968E2A/)

## Problem Statement

用户粘贴存在 AI 中文字幕的视频链接后，BiliScribe 未交付该字幕。项目实际已经从现代字幕接口取得轨道，但随后用“中文字幕资源 ID 必须带本视频 aid+cid 前缀”的规则拒绝了它，继续回退旧接口，最终报告字幕归属错误。用户无法区分“没有字幕”“无法验证”和“已经确认属于其他视频”。

本次定位的直接原因是资源格式假设过强：语言为中文不意味着资源 ID 一定携带视频身份。无前缀 ID 只能说明不能从 ID 还原归属，不能单独证明串轨。Python 与云端 Worker 都存在这一假设；实际在线复现只覆盖了本地客户端，云端结论来自代码检查。

历史上确实出现过旧接口返回不匹配内容的问题，因此修复必须保留缓存和导出前的归属验证，不能将所有不透明 ID、所有作者相同的轨道或所有 HTTP 200 响应一律放行。

## Solution

用户继续使用现有的链接、语言、分 P 和导出操作。符合下述来源及身份条件的无前缀现代字幕可以提取；明确冲突的轨道继续拒绝；不能验证的轨道显示独立原因。正常现代字幕不得因为旧接口的错误结果而被丢弃，也不得触发音频转写来掩盖字幕接收失败。

归属策略采用两类有效证据：可识别资源格式中的视频身份，以及现代字幕接口对当前视频和分 P 的直接响应来源。两类证据必须明确区分，不能把后一类描述成“已从资源 ID 证明归属”。来源绑定只保证客户端没有混用请求、轨道和缓存；它依赖现代接口遵守请求身份，不能识别所有服务端误配。

## User Stories

1. As a 本地用户, I want 提取现代接口提供的无前缀 AI 中文字幕, so that 已有字幕不会被错误过滤。
2. As a 云端用户, I want 与本地版得到相同的归属判断, so that 部署位置不会改变字幕可信度。
3. As a 字幕使用者, I want 明确属于其他视频的资源被拒绝, so that 导出内容不会串轨。
4. As a 用户, I want 区分没有轨道与轨道无法验证, so that 我能采取合适的重试或反馈操作。
5. As a 用户, I want 字幕接口出错时看到真实错误, so that 我不会误认为视频没有字幕。
6. As a 中文用户, I want 默认中文选择覆盖可接收的 ai-zh 轨, so that 无需改成全部语言才能提取。
7. As a 英文或全部语言用户, I want 保留已有语言筛选行为, so that 本次修复不会导出未选语言。
8. As a 多分 P 用户, I want 每条轨道绑定到实际选择的分 P, so that 相邻分 P 不会共用错误字幕。
9. As a 使用 av 号或短链的用户, I want 链接先解析成规范视频身份, so that 不同链接形式具有相同结果。
10. As a 重复提取用户, I want 安全复用当前视频的有效缓存, so that 第二次提取仍然正确且减少请求。
11. As a 升级用户, I want 无来源证明的旧缓存自动重新查询, so that 历史缓存不会绕过新规则。
12. As a 用户, I want 签名失效或正文暂时为空时按现有流程刷新, so that 可以恢复的字幕不会立即被当作不存在。
13. As a 用户, I want 成功现代字幕不受无效旧接口轨道影响, so that 已取得的可用字幕能够交付。
14. As a 导出用户, I want SRT、VTT、TXT、JSON、Markdown 保留既有格式行为, so that 生成文件可以继续使用。
15. As a 用户, I want 诊断中不出现 Cookie 和完整签名 URL, so that 反馈问题时不会泄露登录态。
16. As a 维护者, I want 用完全离线的公开提取场景复现本次缺陷, so that 不依赖真实账号也能防止回归。
17. As a 维护者, I want 区分明确身份冲突与证据不足, so that 错误提示和后续排查有事实依据。
18. As a 用户, I want 现有 CC/AI 字幕问题按字幕路径解决, so that 处理结果不会被替换为新生成的转写内容。

## Implementation Decisions

1. **视频身份。** 从视频信息解析结果取得规范 bvid、aid、目标分 P 的 cid。现代接口的 pid 必须对应 aid，oid 必须对应该 cid；绑定信息由发起请求的客户端创建，不能从轨道内未经验证的字段复制。不得把首 P 的 cid 套用到其他分 P。
2. **轨道与来源分离。** 元数据解析器只负责解析远端字段，不把成功解析等同于归属通过。请求层保留内部来源记录，包括来源接口类型、规范视频身份、资源 ID、轨道标识、语言和校验策略版本。来源绑定必须关联具体轨道；修改 URL、资源 ID、语言或轨道标识后，旧记录不得继续授权使用。
3. **资源格式分类。** 地址先经过既有安全校验和播放器地址解码，再按明确支持的资源命名格式分类。32 位十六进制资源标识视为不透明 ID，不从其数字开头猜测 aid/cid，也不因语言是中文就认定它属于某个视频。不认识的格式不能默认视为安全。
4. **可识别归属资源。** 对确有身份结构的资源保留本视频匹配要求；确认属于其他身份的轨道拒绝。可靠的返回身份或既有明确作者冲突检查如被触发，也不得被现代来源标记覆盖。作者相同本身不能证明属于同一视频。
5. **现代不透明资源的限定接收。** 仅对当前现代接口直接响应中、地址有效、可正确解析、符合已支持不透明格式、绑定完整且无明确冲突的轨道，允许以“现代请求来源绑定”方式通过。此规则对符合条件的语言统一适用，语言筛选在之后执行。普通调用方传入一条字典、旧接口转来的轨道、来源不明的缓存，均不能自行获得该资格。
6. **旧接口边界。** 旧接口仍可补充经既有身份规则验证的轨道。仅来自旧接口的不透明轨道继续拒绝为“无法验证”；不能通过复制现代来源标签、作者相同、重复请求结果相同、正文非空或时长接近来升级可信度。现代接口为空时，不能把旧接口资源包装成现代结果。
7. **逐轨决策及回退。** 先验证现代响应。只要现代接口已有通过验证的候选轨道，就沿既有语言选择和正文下载路径处理，不为寻找其他轨道无条件访问旧接口；语言不匹配仍显示没有所选语言。列表内无效轨道逐条拒绝并保留原因，不授权其正文或导出，也不抹掉同列表中的合格轨道。现代接口无合格轨道时再按既有限次策略回退旧接口，保留前序失败原因。
8. **明确的结果语义。** 至少区分：可交付、接口确认列表为空、存在轨道但无法验证、明确归属冲突、没有所选语言、正文为空、接口访问或解析失败。没有合格轨道且存在无法验证或冲突时，提取结果为错误并提供原因；不能当作“无字幕”成功完成。只有已知格式或可靠身份字段的直接冲突才使用“属于其他视频”的措辞。正文空与网络错误保留可辨识原因及现有有限刷新能力。
9. **异常传播。** 本地提取编排与云端 HTTP 适配器都须保留上述含义。审查现有“ForeignSubtitleError 转为空列表/ASR”的处理，确保拒绝轨道不会被隐藏为无字幕或被 ASR 成功覆盖。成功数据沿用现有结果结构；必要的错误原因以稳定的机器可读 reason 暴露，并保留面向用户的 message。reason 的具体枚举在两端实现中一致，不必重写其他结果字段。
10. **缓存信任边界。** 列表缓存保存来源和校验策略版本，并绑定完整视频身份及逐轨资源；命中时重新验证上下文和记录的一致性。旧列表缓存没有足够来源证据时当作未命中，重新获取；不得在读取时替旧记录补造现代来源。缓存记录不是防本地文件恶意篡改的签名证明。
11. **正文缓存及导出。** 正文缓存命中必须发生在对应轨道通过当前策略验证之后；正文缓存键至少隔离规范视频身份、cid 与稳定资源 ID，防止同视频不同分 P 混用。下载签名更新不改变稳定资源身份；列表来源过期或版本不匹配时需重新取证后才能导出。遵守现有缓存有效期，不延长凭证和签名的生命周期。
12. **校验完整生命周期。** 列表获取、缓存读回、正文 URL 刷新和最终导出均使用同一套决策语义。不得只修第一次请求而在第二次缓存命中时重新拒绝，也不得只在写缓存前检查而让缓存读回绕过策略。
13. **两端一致。** 本地 Python/httpx 编排与原生 Worker 各自实现同一决策表，沿用现有技术栈，不引入共享运行时或新的字幕服务。两端使用相同的脱敏场景和固定预期结果验证一致性。
14. **诊断信息。** 可输出视频身份、来源类型、拒绝原因和计数；不得保存 Cookie、鉴权头、完整带签名 URL 或原始认证响应。资源 ID 仅在有必要的脱敏诊断中出现；不把本次真实字幕全文作为测试样本。
15. **正文与时长的作用。** 内容、段数与视频时长用于人工核对及异常调查，不能单独授权归属。不新增以片头文字匹配、关键词匹配或固定时长容差代替归属检查的规则。

决策表中的“来源绑定有效”指客户端完成了第 1、2、5 项检查，不只是响应中有一个来源字段。

| 来源与资源情形 | 归属决策 | 对用户的行为 |
| --- | --- | --- |
| 支持的带身份资源，匹配当前视频/分 P，且无冲突 | 通过 | 按语言筛选、下载并导出 |
| 资源或可靠元数据明确指向其他视频/分 P | 拒绝：明确冲突 | 无其他可用轨时显示归属冲突；不导出该轨 |
| 现代接口直接返回的受支持不透明资源，来源绑定有效且无冲突 | 通过：依据现代请求来源 | 按语言筛选、下载并导出 |
| 同样的不透明资源，仅来自旧接口或无来源记录 | 拒绝：无法验证 | 无其他可用轨时显示无法验证；不导出该轨 |
| 记录的视频、分 P、资源或策略版本不一致 | 缓存未命中或记录无效 | 重新查询；不得利用旧记录导出 |
| 所有成功查询均明确返回空列表 | 无轨道 | 显示未取得 CC/AI 字幕 |
| 没有合格轨且存在访问/解析失败 | 接口错误 | 展示对应错误，不宣称字幕不存在 |

## Testing Decisions

用户已确认主要验收边界为“公开提取入口 → mock B 站响应 → 导出文件或用户可见错误”。本地复用公开提取编排和真实 BiliClient，仅替换 HTTP 传输；云端通过 Worker 的 HTTP 提取入口，并 mock 外部 fetch。不能 mock 掉字幕列表发现或归属判断再声称验证了本缺陷。二进制协议和地址解码可保留少量底层测试。

既有先例包括公开提取编排的导出断言、Worker 的登录与提取 HTTP 场景，以及离线字幕保护测试。现有现代接口样例把中文字幕资源构造成 aid+cid 前缀格式，因此未覆盖本次不透明 ID；新增主回归必须经过真实元数据解析、地址解码、归属判定和导出，而不是只给私有谓词添加断言。

合格测试验证返回状态、文件数量及内容、语言/分 P 选择、错误原因，以及被拒绝资源没有发生正文请求。预期文本和时间轴固定写在独立样本中，不能用产品转换器生成期望值。所有外部请求都必须 mock；遇到未声明请求立即失败。测试缓存和导出目录独立，不读取真实凭证。

| 编号 | 场景 | 必须观察到的外部结果 |
| --- | --- | --- |

| T04 | 现代接口为空，旧接口只返回不透明中文资源 | 不导出，报告无法验证，不能误称已证实其他视频 |
| T05 | 现代接口为空，旧接口返回可验证且匹配的轨道 | 保持原有成功路径 |

| T13 | 合格轨与无效轨混合 | 合格轨可交付；无效轨无正文下载、缓存授权或导出 |
| T14 | 只修改来源记录覆盖的资源或轨道身份 | 不能沿用旧绑定授权；需重新获取或报告无法验证 |

### 失败链及修复定位

1. 视频身份解析正常。
2. 现代元数据请求成功，解析出 ai-zh 与资源 URL。
3. 中文字幕分支直接要求资源 ID 以目标 aid+cid 开头，返回不通过。
4. 现代候选被静默过滤；没有合格结果，调用方进入旧接口。
5. 旧接口轨道未通过检查，公开客户端方法抛出“其他视频数据”的异常。
6. 更高层现有编排还可能把该异常转成无轨道并路由 ASR；规范要求保留真实原因。

### 信任假设与完成定义

接收现代不透明资源是一项明确的信任策略：相信现代接口按当前 pid/oid 提供轨道，同时保证客户端来源、身份和缓存不混用。如果现代接口服务端把其他视频的同格式资源放进合法响应，而且没有可核验的冲突字段，本策略仍可能无法发现。重复请求、内容看起来相符和时间轴接近都不能消除这一限制。后续若取得可靠的响应归属字段，应优先验证；本规范不虚构当前解析器尚未取得的字段。

实施完成必须同时具备：主回归的失败到通过证据、两端 mock 场景的公开行为证据、本地目标案例真实提取结果及时间、未验证边界说明。文档存在和既有测试通过都不等于本缺陷已经修复。
