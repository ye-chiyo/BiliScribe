# BV1NG9xBUEju 字幕提取失败记录

## 问题

对视频 `BV1NG9xBUEju` 提取字幕时，旧接口有时返回一条 `ai-zh` 轨，但导出的资源不属于当前视频。播放器是否实际展示了该视频的“中文 AI”轨道，当前没有通过可重复的播放器网络证据确认。

## 已验证事实

- 视频信息接口返回目标视频的 `aid=116488438549326`、`cid=37950522219`。
- `/x/v2/subtitle/web/view` 返回 HTTP 200 的空 Protobuf（脱敏后为 `0a00`），解析得到 0 条轨道；替换语言偏好参数后仍为空。
- `/x/player/wbi/v2` 返回空字幕列表，`need_login_subtitle=false`。
- `/x/v2/dm/view` 的字幕字段为空，页面 HTML 也没有可用字幕 URL。
- `/x/player/v2` 偶尔返回 1 条 `ai-zh`，其资源 ID 不含目标 `aid+cid` 归属前缀。现有归属校验拒绝该轨道，因此不会缓存、下载或导出。

本地服务真实作业日志进一步确认调用链：视频信息和 1 个分 P 解析成功；旧接口第 1/3、3/3 轮记录为“返回其他视频的字幕轨”；现代接口刷新仍没有恢复目标轨。归属校验失败后 `get_subtitle_list()` 抛出 `BiliError`，因此正文下载函数没有被调用，服务层直接记录 `status=error`、`files=[]`，这就是“0 条字幕、0 个文件”的直接原因。

## 判断

这次失败不是已经证实的字幕正文下载 bug。当前可验证接口没有提供属于目标视频的可下载字幕；旧接口返回的是其他视频轨道。放宽归属校验会重新产生用户最初遇到的错误字幕，因此不安全。

合理推测包括 B 站接口风控/登录态差异，或播放器展示的字幕来自当前账号/播放器上下文而未被公开接口返回。尚未知晓播放器 UI 所显示的轨道是否确实属于该 `aid/cid`，也未知其正文 URL 是否使用了当前轮换编码。

## 本次改动

- Python 本地版：现代 Protobuf 接口为空且旧接口连续串轨时，显示“未找到属于当前视频的可用字幕轨”，提示先确认播放器确实显示 CC/AI；继续严格拒绝异视频轨。
- JavaScript Worker：同步同一诊断信息，并增加 mock 回归测试；正常网络异常仍保留重试类错误。
- 没有修改 `data/` 或 `output/`，没有引入 ASR，也没有记录凭证、签名 URL 或字幕正文。

## 第三方项目判断

`claude-skill-video-transcribe` 是一个 Claude Skill 加 Python CLI，不是可嵌入的 B 站字幕库。源码用 `yt-dlp` 优先下载 VTT/SRT 字幕，失败后下载音频，再调用 Gemini 或 mlx-whisper 做 ASR；它没有本项目需要的 Protobuf 字幕元数据解析、字幕 URL 解码和 `aid/cid` 归属校验。本次未复用其实现，因为 ASR 回退会越过 BiliScribe 的产品边界。

## 复测边界

自动化测试完全 mock B 站请求，证明 Protobuf 空响应、异视频轨和错误提示的行为稳定。它不能证明当前账号在 B 站播放器 UI 中看到的轨道一定不存在。人工复测时请在同一账号的播放器开发者工具中确认 `/x/v2/subtitle/web/view` 的响应和字幕正文请求，并只提供脱敏的轨道元数据/URL 结构，不要提供 Cookie。

2026-10-19 本地服务真实复测：登录态有效，目标作业完成率 100%，结果为 0 个文件，并显示上述明确诊断。该复测访问了真实 B 站接口，仅保留状态和错误摘要，没有保存凭证、签名 URL 或正文。

## 第三方脚本复测

按其 README 运行 `python Tools/transcribe.py --input <目标链接>`：脚本先调用 `yt-dlp --write-auto-sub --write-sub --skip-download`，输出“无现成字幕”，随后进入音频下载回退。由于 Windows 环境没有 `ffmpeg/ffprobe`，回退失败；脚本本身也没有读取 BiliScribe 登录态。单独运行同款 `yt-dlp` 字幕命令时，目标视频解析到相同 `cid`，但明确输出 `There are no subtitles for the requested languages`，没有生成字幕文件。

随后用本地 BiliScribe 登录态仅在内存中构造 Cookie 请求头，重新运行同款 `yt-dlp` 字幕抓取：退出码为 0，仍没有生成字幕文件，并再次输出 `There are no subtitles for the requested languages`。因此前一次结果不是插件安装不完整或单纯缺少登录态；`ffmpeg/ffprobe` 只影响无字幕后的 ASR 回退。

多视频对照（均使用本地登录态）结果：BiliScribe 对 `BV16hZFB5ERM` 和 `BV11gYd6UEPv` 各获取 1 条轨并生成 1 个文件，对 `BV1NG9xBUEju` 获取 0 条轨；第三方同款 `yt-dlp` 字幕命令对这三个视频均生成 0 个字幕文件并报告没有请求语言的字幕。说明第三方的字幕路径整体无法获取 BiliScribe 通过现代接口拿到的 AI 字幕，不是单一视频或单纯缺少插件安装。

追加真实探测确认：为目标视频补充 WBI 签名、设备/语言头、`preferred_language`、`web_location`、`playlist_switch` 和 `context_ext` 变体后，现代接口仍为 2 字节 `0a00`；正确视频的同接口仍返回包含轨道的 Protobuf。旧接口偶发返回的 `ai-zh` 资源在多次正文探测中覆盖范围不稳定，且资源 ID 不匹配目标 `aid+cid`，不能安全导出。

2026-10-20 原因复核补充：旧 `/x/player/v2` 对目标请求会在 0 条与 1 条 `ai-zh` 轨之间变化；其中一次带缓存破坏参数的请求返回了 HTTP 200 字幕正文，共 869 段、时间轴到约 1660 秒（视频约 1225 秒），但资源 ID 不含目标 `aid/cid`，因此仍不能认定为目标字幕。`/x/player/wbi/v2` 和现代 Protobuf 接口为空。最可能是 B 站旧接口对该视频串配/返回陈旧轨道；真实播放器启用字幕时的元数据请求尚未捕获，所以具体是服务端缓存、数据映射还是额外播放器上下文仍未知。

同一登录态、同一 BiliScribe 客户端的接口差分：

- `BV16hZFB5ERM`：现代接口 1 条，资源 ID 以目标 `aid+cid` 开头，归属校验通过；旧接口 1 条但归属校验失败。
- `BV11gYd6UEPv`：现代接口 4 条，其中中文轨资源 ID 以目标 `aid+cid` 开头；旧接口 1 条且归属校验失败。
- `BV1NG9xBUEju`：现代接口 0 条；旧接口 1 条且归属校验失败。

因此成功视频并不是因为旧接口可靠，而是现代接口提供了目标视频轨道；失败视频缺少这条现代接口数据，只剩下不能安全使用的旧接口串轨结果。
