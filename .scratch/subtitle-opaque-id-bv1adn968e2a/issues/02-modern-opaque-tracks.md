# 02: 让现代接口的无前缀 AI 字幕完成安全提取

**What to build:** 本地与云端首次提取现代不透明字幕时，按规范视频、分 P 和具体轨道的请求来源绑定安全接收并导出。使用父 issue 所指完整规范，信任范围仅为现代接口的当前响应，不保证识别全部服务端误配。

**Blocked by:** 01: 准确区分字幕为空、无法验证、归属冲突与接口失败。

**Status:** ready-for-human

- [x] T01 主回归经过真实客户端、Protobuf 解析、地址解码、归属判断和公开导出，先失败再通过。
- [x] 支持 32 位十六进制不透明资源；来源绑定覆盖视频身份、cid、资源、轨道标识、语言及策略版本，不能靠外部字典字段伪造授权。
- [x] 明确冲突优先拒绝；旧接口不明轨道不因现代来源规则被放行；正文内容与时长不作为授权依据。
- [x] 现代已有合格轨时不请求旧字幕接口；混合列表只交付合格轨。
- [x] 两端验证 T01、T02、T05、T06、T09、T13 及 T14 的当前请求绑定检查，保留现有语言和导出行为。
- [x] 下一票完成前，新接收不透明轨道暂不复用持久缓存，每次重新取得来源证据，确保本票独立交付安全。


## 实现与验证记录（2026-10-28）

- 本地和 Worker 已接收经过当前现代请求来源绑定的受支持 32 位十六进制资源；绑定包含视频、分 P、规范 URL、轨道标识、语言与策略版本，正文请求前后重新检查。
- 不透明资源的列表与正文缓存暂不复用；持久来源记录、缓存迁移和完整刷新生命周期交给票 03。旧接口自称现代来源的字段不能授权，作者相同也不能替代视频归属。
- 保持明确冲突及未知地址/编码的拒绝；现代成功不请求旧接口。混合列表只交付合格轨，修复了本地旧接口混合列表此前整批失败的问题。
- T01 公开路径先红后绿：本地原先抛出 UnverifiedSubtitleError，Worker 原先返回 error；修复后两端均从编码现代资源导出固定样本文本，且没有旧字幕接口请求。两种已支持轮换编码及纯数字 32 位不透明 ID 均覆盖。
- 当前请求的指纹绑定已实现；离线公开场景覆盖旧接口伪造来源、明确作者冲突、无效地址及混合轨道。持久记录修改导致失效的外部行为验证仍属于票 03，不把本票测试宣称为完整缓存验收。
- 最终验证：Python pytest 73 passed；离线维护 unittest 5 passed；独立字幕保护脚本通过；Worker 先构建后完整测试 25 passed；git diff --check 通过。
- 所有新增测试仅 mock 外部 HTTP 与时间，不读取真实凭证，不访问真实 B 站。真实视频及集成分支用户体验由主代理统一验证。
