# 02: 让现代接口的无前缀 AI 字幕完成安全提取

**What to build:** 本地与云端首次提取现代不透明字幕时，按规范视频、分 P 和具体轨道的请求来源绑定安全接收并导出。使用父 issue 所指完整规范，信任范围仅为现代接口的当前响应，不保证识别全部服务端误配。

**Blocked by:** 01: 准确区分字幕为空、无法验证、归属冲突与接口失败。

**Status:** ready-for-agent

- [ ] T01 主回归经过真实客户端、Protobuf 解析、地址解码、归属判断和公开导出，先失败再通过。
- [ ] 支持 32 位十六进制不透明资源；来源绑定覆盖视频身份、cid、资源、轨道标识、语言及策略版本，不能靠外部字典字段伪造授权。
- [ ] 明确冲突优先拒绝；旧接口不明轨道不因现代来源规则被放行；正文内容与时长不作为授权依据。
- [ ] 现代已有合格轨时不请求旧字幕接口；混合列表只交付合格轨。
- [ ] 两端验证 T01、T02、T05、T06、T09、T13 及 T14 的当前请求绑定检查，保留现有语言和导出行为。
- [ ] 下一票完成前，新接收不透明轨道暂不复用持久缓存，每次重新取得来源证据，确保本票独立交付安全。
